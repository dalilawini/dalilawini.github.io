SYSTEM ARCHITECTURE

ESP-NOW Smart-Home Hub with a Touchscreen

An ESP32 hub with a 320×240 touchscreen that collects indoor and outdoor weather, switches lamps and pairs new devices over ESP-NOW. It needs no router, no app and no cloud server, and the data never leaves the house.

01 / SYSTEM OVERVIEW

One hub, every device in the house

Battery-powered sensor nodes and a lamp relay board talk directly to the hub. Inside the hub, the radio, the device registry, the display and the hand-written screen logic are separate modules, so each one can change on its own.

02 / HARDWARE PLATFORM

ESP32 with a resistive touchscreen

The hub runs on an ESP32-2432S028R ("Cheap Yellow Display"): an ESP32 with an ILI9341 SPI display and an XPT2046 touch controller. The display and the touch controller each have their own SPI bus.

MOSI 13, MISO 12, SCLK 14, CS 15, DC 2. Driven by TFT_eSPI, with LVGL drawing into a buffer one tenth of the screen.

XPT2046 touch

A separate SPI bus (CLK, MOSI, MISO, CS) for the resistive touch controller, with its interrupt on GPIO 36.

GPIO21

Backlight

The backlight is switched on at boot, active HIGH.

Wi-Fi radio

ESP-NOW, channel 1

All devices talk on a fixed channel. The radio switches to access-point mode only during the pairing window.

NVS

Flash storage

Paired devices, their roles and the last lamp states are kept with the Preferences API and survive power cuts.

Huge APP

Partition scheme

The firmware is about 1.4 MB, more than the default 1.2 MB app slot, so it uses the 3 MB app partition.

03 / FIRMWARE MODULES

One job per module

The radio never touches the display. Packets are copied in the Wi-Fi callback, parsed in the main loop, recorded in the registry and only then drawn by LVGL.

01

EspNowManager

Owns the radio: it receives packets, sends commands to devices, opens the pairing access point and collects the ESP-NOW delivery reports.

RECEIVE → PARSE → REGISTER → ROUTE → DRAW

A pairing request from the touchscreen only sets a flag. The access point is started from the main loop, never inside an LVGL callback, so the UI and the radio stay in separate execution contexts.

02

DeviceRegistry

Remembers every device that has talked to the hub, identified by its MAC address, with its role and latest values.

MACDevice identity
ROLEOutdoor, Indoor, Bedroom…
RSSISignal strength, last seen
10Devices, offline after 5 min
03

SensorData & DisplayManager

SensorData turns the JSON payload into a temperature reading or a switch announce. DisplayManager drives the TFT, touch and LVGL timer, and routes each packet to the right screen according to the device's type and role.

05 / PAIRING

One-tap pairing from the touchscreen

Tapping + Pair device opens the hub's ESP-NOW-GATEWAY access point for 60 seconds. A new device joins it, learns the hub's MAC address, and the hub returns to ESP-NOW straight away.

⌁
Useful straight after the first boot

Outdoor and Indoor are unique roles: giving one to a device takes it from the previous one. Until an Outdoor sensor is chosen, any new temperature sensor feeds the main card, so the hub shows data before anything is configured.

06 / LAMP CONTROL

Commands confirmed by the radio

The relay board does not report its state, but the hub doesn't trust a command blindly. The ESP-NOW delivery report tells it whether the board received the packet, and the screen reacts to that.

08 / USER INTERFACE

Four screens on a 320×240 display

Weather is the home screen. Tapping anywhere on it opens Lights, which returns home after 30 seconds without a touch. Every page has a ☰ menu.

A

Weather

Outdoor temperature in large digits, an animated sky icon, session high and low, humidity, dew point, comfort level and feels like, plus an indoor column.

B

Trends

A live chart of the last 48 outdoor readings, temperature and humidity, with an auto-scaling axis.

C

Lights

Three lamps on one relay board: tap to switch, All on / All off, and a ✓ or ✗ for every command based on the delivery report.

D

Devices

Every device with its MAC, signal strength, last-seen time and online state, a NEW badge, role assignment and forget.

09 / END-TO-END

From a sensor reading to a lamp switching

The hub closes the loop between the devices around the house: it reads the sensors, shows their data and sends commands back out over the same radio.

01 SENSE ESP8266 nodes
02 TRANSMIT ESP-NOW + JSON
03 IDENTIFY Registry by MAC
04 ROUTE Type + role
05 DISPLAY LVGL screens
06 CONTROL Relay commands
⌁
Engineering focus

The screens are designed visually in EEZ Studio, which regenerates screens.c on every build. The behaviour lives in hand-written files (weather_ui, lights_ui, devices_ui, navigation) that find widgets by name, so the UI can be restyled without touching the logic. Adding a new device type is five steps: define its JSON, add a device type, detect it, route it and give it a screen.
